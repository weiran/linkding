# Shared reader articles

GET `/api/bookmarks/<id>/reader-article/` uses normal token auth and owner-only bookmark lookup. Returns `{version, captureID, url, title, html, assets}`. Version is `readability-shared-1`. Each asset contains SHA256 `id`, `mimeType`, base64 `data` (colour JPEG up to 1200×1600), and `kindleData` (grayscale JPEG up to 600×800). HTML uses `reader-image:<id>` URLs; clients must rewrite them to private local files. Block IDs are stable content hashes with duplicate occurrence indexes; preserve them rather than re-extracting the HTML.

Captured Dingbat HTML attachments are preferred over snapshots. When neither exists, fetch the public original through Linkding's SSRF-guarded HTTP client. Publisher scripts and external resources are disabled in JSDOM; the vendored Mozilla Readability parses on the server. Bleach removes publisher markup/attributes outside the allowlist. Images use the guarded HTTP client, retain aspect ratio, and are re-encoded with Pillow. Missing images become alt text. Source, image size/count/time budgets bound work. Authentication cookies are not imported from Safari; only content actually captured/uploaded there is available.

Canonical documents and their image data are cached privately under data/reader by bookmark URL, source identity and extractor version. Cache publication is atomic; older document caches for the same bookmark are removed when a new version is published. Deleting a bookmark currently leaves its unserved cache file for later maintenance. The cache is not served statically. Each API access still checks ownership. Preparation failure returns 503 and does not replace the last good client copy.

Dingbat installs this HTML and images without re-extraction, preserves passage IDs and excludes canonical copies from raw capture uploads. The KOReader plugin downloads the same document, writes Kindle image variants beside it, and uses shared passage IDs with percentage fallback. Progress API remains independent; stock Linkding browser reader is not integrated.

Validation: 101 affected server API tests passed; 281 Dingbat simulator tests passed on the existing iPhone 18 Pro, iOS 27.0. A live disposable-account test against Otto verified canonical capture identity, server image delivery to Dingbat's offline cache, progress upload/restoration across two independent stores, and start-over sync. Account and bookmark removed. KOReader plugin was checked against upstream source and tested in a Lua runtime for offline persistence/downloads, image paths, progress ordering, queued finish and URL/path validation. Physical Kindle install, Wi-Fi/TLS, image layout and passage restoration remain unverified because the device was unavailable.
